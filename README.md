# Smart Wearable System for Gold Jewellery Hallmark Recognition and Readability Assessment

*(Review 2 code repository, Wearable Computing BCSE315L, Team 37, VIT Vellore. Paper title: "Design of a Smart Wearable System for Gold Jewellery Hallmark Recognition and Readability Assessment". Earlier working title: "Smart Wearable Gold Detection: Hallmark Reading with Calibrated Rejection".)*

Simulation-based evaluation of a wrist-worn vision-assisted system that **reads the characters of a gold-jewellery hallmark-style inscription**, rejects unreliable readings with a calibrated rejector, and tells the wearer how to retake a poor capture.

**This is not a gold authentication, purity, composition or BIS-certification tool.** It performs OCR on an inscription and never states whether an item is genuine or what it is made of.

## Quick start: the acquisition application (webcam + image upload)
```
pip install -r requirements.txt --break-system-packages     # plus system package tesseract-ocr (eng)
python -m acquisition.server                                 # open http://127.0.0.1:5060
python -m acquisition.server --demo-video demo/test_feed_clean.avi --demo-video demo/test_feed_glare.avi   # machine WITHOUT a camera
python -m acquisition.server --host 0.0.0.0                  # also reachable by the wrist unit on the same Wi-Fi (POST /api/wearable/upload)
```
In the page: choose **Webcam (OpenCV)**, pick a camera, *Start preview*, *Capture frame*, *Process image* (or *Retake*); or open **Upload image** and choose a close-up photograph. Every captured/uploaded image is saved under `captures/` (with a metadata JSON and `processing_log.jsonl`), read back, validated and processed by the same pipeline. A normal laptop webcam is fixed-focus and usually cannot resolve millimetre-high hallmark characters: use upload with a close-up/macro photograph, or a USB macro camera/microscope.
**Webcam testing status:** the sandbox used for development had no camera. The OpenCV capture/preview/disconnect code was tested with `demo/test_feed_*.avi` (recorded videos of SYNTHETIC frames) via `cv2.VideoCapture`; **it has not been tested with a physical webcam**. The upload path and the browser UI are covered by automated tests (`tests/test_acquisition.py`, `tests/test_ui_playwright.py`; screenshots in `docs/screenshots/`).

## Demonstration (about 5 minutes, no hardware needed)
1. `pip install -r requirements.txt --break-system-packages` (plus system package `tesseract-ocr`), then `python -m acquisition.server --demo-video demo/test_feed_clean.avi --demo-video demo/test_feed_glare.avi` and open http://127.0.0.1:5060 (with a real camera, omit the demo videos).
2. Webcam (OpenCV) tab: choose the test video, Start preview, Capture frame, Process image: the clean feed is accepted; the glare feed is rejected with a recapture hint. Camera source here is a recorded video of synthetic frames.
3. Upload tab: upload any close-up image (a synthetic example is rendered by `acquisition/synthetic.py`).
4. Wearable tab / HTTP: `curl -X POST --data-binary @frame.jpg -H "Content-Type: image/jpeg" http://127.0.0.1:5060/api/wearable/upload` returns the three-line reply. This is what the proposed (unbuilt) wrist unit would send; it has only been exercised with a Python client.
5. `pytest tests -q` runs the 27 automated tests.

## System and honest status
* **Wrist camera unit (PROPOSED, not built, not tested):** one **Seeed XIAO ESP32S3 Sense** board with its **proposed camera module** (OV5640 with autofocus as listed by the vendor; Seeed also says boards may ship with an OV3660, so the fitted module is unconfirmed; primary sensor, on the board-to-board connector), a white LED (illumination only, NPN driver), a push button and an SSD1306 OLED. Press the button -> LED on -> JPEG -> one HTTP POST -> the reply (3 lines of text) is shown on the OLED. Firmware: `hardware/wearable_firmware/wrist_unit/wrist_unit.ino` (about 80 lines, no OCR/ML, no other protocol). Wiring: `diagrams/wearable_reference_schematic.png`. The wearable camera has never captured an image. The laptop webcam is a separate path and is not evidence for it.
* **Companion (IMPLEMENTED, Python):** the unchanged pipeline (quality, localisation, RapidOCR + Tesseract, readability RF, ExtraTrees + isotonic rejection, guidance) behind `acquisition/server.py`. Three acquisition sources feed the same `process_stored()` entry point: laptop webcam (OpenCV), image upload, and the wearable HTTP endpoint `POST /api/wearable/upload` (see `docs/wearable_http_interface.md`).
* **Wokwi (SIMULATED, limited):** `hardware/wokwi_xiao_s3/` runs the firmware on Wokwi's XIAO ESP32-S3 board with an OLED, a button and an LED. Observed: it compiles and boots, and the camera probe fails (`ESP_ERR_NOT_SUPPORTED`) because **Wokwi has no camera part**. Not observed: button, OLED screens, Wi-Fi POST, any frame. No camera is simulated.
* **Tested:** the HTTP receiver with a Python client (`tests/test_wearable_http.py`): reply equals a direct pipeline call, stored bytes identical, bad bodies rejected. **NOT tested:** any physical hardware, the camera, the firmware's POST, a real Wi-Fi link, the laptop webcam with a physical camera, TLS/authentication.
* All data are synthetic (`data/DATASHEET.md`). Latency/memory were measured on a 2-vCPU x86 sandbox, **not** on a Raspberry Pi.

## Headline results (synthetic test split: 48 items / 288 images)
* Best OCR: RapidOCR (PP-OCR recogniser) on the raw ROI: exact 0.510, CER 0.271; Tesseract exact 0.188. Classical enhancement *lowered* accuracy.
* Raw OCR confidence is a poor reject signal (AURC 0.274, ECE 0.144). A learned rejector on dual-engine uncertainty features: AURC 0.181 (paired dAURC -0.09, 95 % CI [-0.146, -0.041]).
* Adding image-quality features to that rejector did **not** measurably improve AURC (dAURC 0.000, CI [-0.009, +0.010]); quality features do improve readability-proxy prediction slightly and power the recapture hints (top-1 cause hit 0.674 vs 0.185 random).
* Readability (proxy) macro-F1 0.804 (quality only), 0.826 (+OCR uncertainty).
* Dev-selected risk thresholds do **not** transfer exactly to the test split (see T8/T8b).

## Troubleshooting
* `TesseractNotFoundError`: install the system package (`sudo apt install tesseract-ocr`, or the Windows/macOS installer) and make sure `tesseract` is on PATH.
* `pip install` refuses with "externally managed environment": use a virtual environment, or add `--break-system-packages`.
* Webcam tab shows no cameras: expected on machines without one; start with `--demo-video demo/test_feed_clean.avi` (recorded synthetic frames).
* Port already in use: `python -m acquisition.server --port 5071`.
* Browser UI test fails or hangs: run `playwright install chromium`; the test is timing-sensitive, re-run once before investigating.
* Numbers differ slightly after re-running the scripts: OCR engine versions affect exact values; seeds are fixed in `configs/default.json`. Latency (`07`) is machine-dependent.
* The wearable endpoint is plain HTTP with no authentication: use only on a trusted local network.
